You are reading a course's existing teaching material: session slide decks and
existing Technical Reference (TR) docs. Your job is to write ONE reusable house
style guide that another writer could follow to produce an indistinguishable
new TR doc.

Do not summarise the subject matter. Describe the CRAFT.

Cover exactly these headings:

## Hook patterns
How do these docs open? Quote 3 real opening hooks verbatim, then state the
shared pattern in one sentence.

## Recap tables
Quote one real recap table. State the column names used, the level of detail,
and the tense.

## Section rhythm
Typical section length, where tables appear, where code
appears, how a step is introduced before it is shown.

## Design-decision sections
Quote one real "alternatives" table. State how the choice is justified.

## Sentence and vocabulary rules
Sentence length. Contractions or not. How the actors are named (developer /
system / user / model). Words these docs consistently avoid.

## Formatting conventions
Exact tags used and when: `<details>`, `<MultiLineNote>`, tables, backticks,
link format. Quote one real example of each you find.

## Callout style
How the hook question is phrased and formatted.

## Try It Yourself style
Quote one real example. State the difficulty level and how the ideas table is
structured.

## Anti-patterns observed
Anything the existing docs consistently do NOT do.

## What NOT to report
Do not prescribe a section ORDER or a required list of sections. The docs you
are reading predate the current authoring rules, and section order is decided
by those rules, not by you. Report how sections are WRITTEN, never which
sections must exist or in what sequence.

Quote real lines from the material wherever you can -- a guide made of real
examples is followed correctly; a guide made of adjectives is not.
